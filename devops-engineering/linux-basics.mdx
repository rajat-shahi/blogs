If you're coming to Linux for the first time, the terminal can feel intimidating. This post covers the handful of concepts and commands that get you through 90% of day-to-day work.

## The filesystem

Everything in Linux is a file, and every file lives somewhere under a single root directory: `/`. There's no `C:\` or `D:\` — just one tree.

Some directories you'll run into constantly:

| Path | What's there |
|------|--------------|
| `/home/<user>` | Your personal files, usually shortened to `~` |
| `/etc` | System-wide configuration files |
| `/var` | Logs, caches, and other data that changes often |
| `/usr` | Installed programs and their supporting files |
| `/tmp` | Temporary files, cleared on reboot |

## Navigating around

<CodeGroup>
```bash Move around
pwd          # print working directory — where am I?
cd /var/log  # change directory
cd ..        # go up one level
cd ~         # jump back home
ls -la       # list files, including hidden ones, in long format
```

```bash Look inside files
cat file.txt        # dump the whole file
less file.txt       # scroll through it a page at a time
head -n 20 file.txt # first 20 lines
tail -f app.log     # follow a growing log file live
```
</CodeGroup>

<Tip>
  `ls -la` is one of the most-typed commands in Linux. `-l` gives you the long listing (permissions, owner, size, date); `-a` shows dotfiles like `.bashrc` that are hidden by default.
</Tip>

## Permissions

Every file has an owner, a group, and a set of permissions for three groups of people: the owner, the group, and everyone else. Running `ls -l` shows them as a 10-character string:

```
-rwxr-xr--  1 alice devs  1024 Jan  1 09:00 deploy.sh
```

Breaking that down:

- The first character is the file type (`-` for a regular file, `d` for a directory).
- The next three (`rwx`) are the **owner's** permissions: read, write, execute.
- The next three (`r-x`) are the **group's** permissions.
- The last three (`r--`) are for **everyone else**.

To change permissions, use `chmod`:

```bash
chmod +x deploy.sh       # add execute permission for everyone
chmod 644 notes.txt      # owner: read/write, group & others: read-only
chmod u+w,g-w shared.txt # owner gets write, group loses write
```

The numeric form (`644`, `755`, etc.) adds up read (4), write (2), and execute (1) for owner/group/other respectively. `755` means `rwx r-x r-x` — the classic "executable script" permission.

To change who owns a file, use `chown`:

```bash
sudo chown alice:devs deploy.sh
```

## Working with processes

<Steps>
  <Step title="See what's running">
    ```bash
    ps aux       # snapshot of every process
    top          # live, updating view (press q to quit)
    ```
  </Step>
  <Step title="Find a specific process">
    ```bash
    ps aux | grep nginx
    ```
  </Step>
  <Step title="Stop it">
    ```bash
    kill 1234        # ask process 1234 to terminate gracefully
    kill -9 1234     # force-kill it if it won't respond
    ```
  </Step>
</Steps>

## Piping and redirection

Linux commands are designed to be chained together. The output of one becomes the input of the next:

```bash
cat access.log | grep "404" | wc -l   # count how many lines contain "404"
ls -la > listing.txt                  # write output to a file (overwrite)
echo "done" >> notes.txt              # append output to a file
```

<Warning>
  A single `>` overwrites the target file completely. Use `>>` if you want to append instead of losing what's already there.
</Warning>

## A cheat sheet to keep nearby

| Command | Purpose |
|---------|---------|
| `man <command>` | Read the manual for any command |
| `whoami` | Show the current user |
| `df -h` | Disk space, human-readable |
| `du -sh <dir>` | Size of a directory |
| `grep -r "text" .` | Search recursively for text in files |
| `find . -name "*.log"` | Find files by name pattern |
| `history` | Show recently run commands |
